# LAVi-SPICA 学生向けガイド

LAVi-SPICAでは、**予想する → 書く → 実行する → 比べる → 説明する**という順序でPythonを学びます。正解を眺めることより、短いコードを自分で直して動かすことを優先してください。

## 1. lessonを始める

ホーム画面の「次のlessonへ」または「学習コース」を選びます。lesson 01から順に進めると、前の文法を使いながら新しい内容を学べます。

学習記録は現在のブラウザへ自動保存されます。同じPCでも、別のブラウザ、別のユーザー、シークレットウィンドウでは別の記録になります。

## 2. 解説を読む

### 到達目標

最初に、lessonを終えたときに何ができればよいかを確認します。すべてを暗記する必要はありません。コードを見ながら処理を説明し、一部を変更して動かせることを目標にします。

### 考え方と構文

詳しい解説では、文法の役割だけでなく、記号と処理順序も確認します。

- `=`：右辺を先に計算し、その結果を左辺の変数へ代入します。
- `()`：関数を呼び出し、引数を渡します。
- `[]`：listの作成、index、sliceに使います。
- `{}`：dictの作成や、f-string内の式に使います。
- `:`とインデント：`for`、`if`、`def`などの処理範囲を表します。

「処理を追跡する」表では、各行の実行後に変数や出力がどう変わるかを上から順に読みます。

## 3. Pythonエディタで試す

「例題を右のエディタへ」を押すと、コードがエディタへ入ります。実行する前に、表示内容や変数の値を予想してください。

- **実行**：コードを動かします。`Ctrl + Enter`または`⌘ + Enter`でも実行できます。
- **停止**：終わらない繰り返しなどを中断します。
- **初期化**：lessonの開始コードへ戻します。
- **コンソール**：標準出力とエラーを表示します。
- **変数**：実行後の主な変数名、型、値を表示します。
- **図**：Matplotlibで作成した図を表示します。
- **生成ファイル**：コードが作成した小さなファイルを保存します。

初回の実行ではPython環境の準備に少し時間がかかります。

## 4. 練習問題を解く

練習問題では、`x`、`n`、`r`、`nums`などの短い変数名を中心に使います。まず処理へ集中し、慣れてから役割が分かる名前へ書き換えます。

1. 問題文から「与えられた値」と「作る結果」を整理します。
2. 開始コードを開き、必要な行を書き足します。
3. 実行し、出力またはエラーを読みます。
4. 分からないときは、ヒントを一つだけ開きます。
5. 自動確認へ合格した後、解答例と比べます。

自動確認は、出力や必要な構文の最低条件を調べます。合格しない場合は、空白、改行、変数名、指定された関数や処理を確認してください。

## 5. 事後学習で定着させる

各lessonには、次の4問があります。

- **知識・説明問題2問**：処理の順序、結果が変わる理由、文法の使い分けを自分の言葉で答えます。
- **コード問題2問**：開始コードへ処理を書き足し、実行と自動確認を行います。

最初は資料と解答例を閉じたまま解きます。行き詰まったときだけヒントを開き、最後に解答例で考え方を確認します。質問や振り返りのメモ欄は任意です。学習の中心は4問の問題演習です。

## 6. エラーを直す

エラー画面の最後の行に、種類と手掛かりが表示されます。

| エラー | 主な確認点 |
|---|---|
| `SyntaxError` | 引用符、括弧、コロン、文法の並び |
| `NameError` | 変数名の綴り、代入より前に使っていないか |
| `TypeError` | 数値と文字列など、異なる型を直接計算していないか |
| `IndexError` | listやtupleの範囲外を指定していないか |
| `KeyError` | dictに存在しないキーを指定していないか |
| `IndentationError` | `for`、`if`、`def`の内側が同じ幅で字下げされているか |

tracebackの最後と行番号を読み、1か所だけ修正して再実行します。途中の値が分からないときは、一時的に`print()`を追加します。

## 7. 学習記録を保存する

「進捗・保存」では、lesson完了数、練習問題の合格数、コード下書きを確認できます。

学習記録はCookieではなく、このサイト用のブラウザ保存領域に記録されます。通常の再読み込みやブラウザ終了では消えません。ただし、「Cookieとサイトデータを削除」「閲覧データを削除」などの操作では、学習記録も削除されることがあります。

大切な記録は「進捗JSONを書き出す」で保存してください。別の端末では「進捗JSONを読み込む」から復元できます。読み込み前の記録は置き換わるため、必要なら現在の記録も先に書き出します。

確認テストで登録した学籍番号と氏名は、学生用NUメールと結び付けて保存されます。そのため、ブラウザのサイトデータを削除した場合や別の端末を使う場合でも、同じNUメールで確認テスト入口を開けば復元されます。lessonの学習記録はNUメールには同期されないため、進捗JSONで管理してください。

## 8. 授業当日の確認テスト

確認テストには、原則として次の二つを使います。

- **スマートフォン**：教室内QR認証
- **PC**：問題の表示、Pythonコードの実行、回答の提出

スマートフォンとPCの両方で、学生用NUメール（`@g.nihon-u.ac.jp`）へログインできる状態にしてください。

### 初回だけ行う登録

最初のQRコードを読み取ったとき、学籍番号と氏名を入力します。

- 新形式の例：`21B11001`
- 旧形式の例：`01001`
- 英数字はすべて半角で入力します。
- 氏名は全角・半角のどちらも使えますが、空白を除いて2文字以上必要です。

登録内容は学生用NUメールと結び付けられ、次回から自動的に復元されます。別の学籍番号が同じNUメールへ登録されている場合は、教員へ申し出てください。

### QR認証

1. 教室のスクリーンに表示されたQRコードをスマートフォンで読み取ります。
2. Googleアカウントを選ぶ画面が出た場合は、学生用NUメールを選びます。
3. 「認証が完了しました」と表示されるまで待ちます。

QRコードは短い間隔で変わり、受付時間も限られています。古い画像や共有されたURLでは認証できないことがあります。必ず教室のスクリーンに表示されている現在のQRコードを読み取ってください。

授業回によって、QR認証は1回または2回です。2回目を行う時刻は教員が案内します。

### PCで問題を開く

1. Google Classroomなどで案内された「PC小テスト入口」をPCで開きます。
2. 学生用NUメールで本人確認されていることを確認します。
3. 必要なQR認証が終わるまで待機します。
4. 教員が小テストを開放すると、同じ時刻から全員の制限時間が始まり、問題画面が自動的に開きます。

PC小テスト入口のURLだけを他の人へ伝えても、必要なNUメールと教室内QR認証がない場合は問題を開けません。問題画面だけを直接開くこともできません。

### 回答と提出

確認テストには、選択問題、短答問題、短いPythonコード問題が含まれます。

- コード問題は「実行して確認」で出力やエラーを確認できます。
- テスト中に正解や採点結果は表示されません。
- 残り時間が0になると、作成済みの回答が自動提出されます。
- 回答終了後に短い送信猶予が設定されることがあります。これは通信送信だけの時間で、新しく回答を始める時間ではありません。
- 提出は1回だけです。通信エラーが表示された場合は、画面を閉じずに「同じ回答を再送する」を押します。

第2認証が「提出後」に設定されている回では、回答は一度仮受付となります。教員が表示する2回目のQRコードを読み取ると、評価対象として確定します。

回答はクラウドへ記録されるため、通常は回答JSONを保存してGoogle Classroomへ添付する必要はありません。得点や返却方法は教員の指示に従ってください。

## 9. うまく表示されないとき

1. 学生用NUメールでログインしているか確認します。
2. ページを一度再読み込みします。
3. ChromeまたはEdgeの最新versionで開きます。
4. シークレットウィンドウではなく通常のウィンドウを使います。
5. それでも開かない場合は、画面に表示されたメッセージを教員へ見せてください。

授業中は、複数タブや複数端末で同じ小テストを同時に開かないでください。
