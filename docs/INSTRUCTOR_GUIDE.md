# 教員向け授業運用ガイド

## 1. 教材の位置付け

LAVi-SPICAは、Python文法を長時間板書して暗記させるための教材ではありません。短いコードを一緒に入力し、次の行動を反復するための教材です。

1. 実行前に予想する
2. 実行して観察する
3. 一度に一条件だけ変える
4. 結果を比較する
5. コードと結果の関係を説明する
6. 条件、コード、必要ならSeedを残す

前半の基礎を、Generative Art、重力多体系計算、データ解析などの後半アプリへ接続することを想定しています。

## 2. 授業前の準備

- 授業用URLをLMSへ掲載
- 教員PCと学生PCの両方でURLを開く
- 同一教室・同一ネットワークでPythonの初回実行を確認
- `cdn.jsdelivr.net`への接続を確認
- 第1回の授業開始前にページを一度開かせ、Pythonを初期化してもよい
- 結果JSON、進捗JSON、スクリーンショットの提出方法を決める
- AI利用方針と「説明できること」を評価条件として明示

## 3. 共通する100分構成

| 時間 | 内容 | 学生の証拠 |
|---:|---|---|
| 0–20分 | 前回範囲の小テスト。第1回は診断 | 結果JSONまたはLMS記録 |
| 20–30分 | 頻出誤答の確認、本日の到達目標 | 誤答理由の短い説明 |
| 30–55分 | 一斉入力1：最小概念 | 実行前予想と出力 |
| 55–75分 | 一斉入力2：組合せ・改変 | 変更前後の比較 |
| 75–92分 | 練習問題 | コード、合格記録、説明 |
| 92–100分 | Exit Ticket、事後学習案内 | 一文の観察と次の疑問 |

各sessionには、内容に合わせた詳細時間割が教員モードに内蔵されています。

## 4. 第1回：変数・print・f-string

### 到達目標

- `=`が代入であり、右辺を先に評価することを説明
- `int`、`float`、`str`、`bool`を変数へ代入
- `print()`で値、意味、単位を表示
- f-stringで式と書式を埋め込む

### 初回20分

本格的な採点より、診断として利用します。全範囲の基礎問題から出す場合でも、点数で序列化せず「どこから支援が必要か」を確認します。

### 強調点

変数名はコンピュータだけでなく、人間へ意味を伝えます。`x`を禁止するのではなく、長く残る物理量には`temperature_c`のような名前を使う理由を示します。

## 5. 第2回：list・dict・tuple・メソッド

### 到達目標

- 順序付きデータ、キー付き記録、変更しない組を使い分ける
- indexが0始まりで、sliceのstopを含まないことを説明
- `append()`などのメソッドを使う
- 関数とメソッドの呼び方を見分ける

### 強調点

データ構造は「どれが高度か」ではなく、データの意味に合わせて選びます。測定値の列、試料記録、座標を比較すると理解しやすくなります。

## 6. 第3回：math・range・for

### 到達目標

- `import math`と代表関数を利用
- `range(start, stop, step)`を具体列へ展開
- `for`とインデントを使う
- ループ変数を数式へ組み込む

### 強調点

`range(5)`の最後が4であること、反復回数、ループ変数の変化を必ず口頭で確認します。NumPyの前に、反復で何をしているかを理解させます。

## 7. 第4回：比較・if・論理演算

### 到達目標

- 比較式が`bool`を返すことを説明
- `if`、`elif`、`else`で処理を選ぶ
- `and`、`or`、`not`を使う
- `for`と`if`で抽出・分類する

### 強調点

境界値を重視します。例えば70点を合格とする場合、`>`か`>=`かを具体的に検証させます。

## 8. 第5回：def・return・デバッグ

### 到達目標

- 入力、処理、出力を関数へ分解
- 仮引数と実引数を区別
- `return`と`print()`を区別
- tracebackと小さい入力で原因を局所化

### 強調点

関数化はコードを短く見せるためだけでなく、同じ規則を検証可能な単位へ分けるためです。AI生成コードの説明にも直接つながります。

## 9. 第6回：オブジェクトとNumPy基礎

### 到達目標

- 変数、参照、オブジェクトの関係を概念的に説明
- mutableなlistの共有参照とcopyを観察
- classとinstanceを最小例で確認
- ndarrayのshape、dtype、ベクトル化を使う
- 配列には`math`ではなくNumPy関数を使う

### 難度調整

class・継承の細部は発展扱いです。初心者の最低到達は、`obj.method()`、参照共有、NumPy配列とlistの違いまでとします。

## 10. 第7回：データ解析とMatplotlib

### 到達目標

- ファイル読込後に`shape`、`dtype`、先頭行を確認
- 列抽出、欠損値、有限値maskを扱う
- CSVとNumPy形式の保存目的を区別
- 軸名、単位、legendを持つ図を作る
- 外れ値・相関を図だけから断定しない

### 強調点

「データを読んだら、まず覗く」を共通手順にします。可視化では、描画命令より、何を比較し、軸と単位をどう伝えるかを評価します。

## 11. 小テスト運用

詳しくは [`QUIZ_OPERATION.md`](QUIZ_OPERATION.md) を参照してください。

標準設定：

- 制限時間：20分
- 問題数：10問
- 範囲：前回session
- Seed：日付とsession番号を含める
- 提出：結果JSON

教員モードの集計はクライアント側だけで行います。サーバーへ個人情報を送信しません。

## 12. 受講人数別の運用

### 10名程度

- 全員のエディタを1回以上直接確認
- 練習後、1人30秒で変更内容を共有
- 小テスト誤答を個別に短く確認

### 20名程度

- 2人組を一次相談先とする
- 教員は「実行不能」「問いが立たない」「境界値が不明」の学生を優先
- 4人組内で結果説明を行う

### 30名程度

- 3〜4人のホームグループを固定
- 質問順を「エラー名確認 → 隣席 → グループ → 教員」とする
- 合格表示だけでなく、グループ内で一行説明を求める

### 30名超

- 個別コード添削を前提にしない
- 進捗と自動確認を巡回順の目安にする
- 進度の速い学生には答えではなく、エラーの読み方を支援させる
- Exit Ticketの頻出疑問を次回冒頭でまとめて扱う

## 13. 欠席者・事後学習

欠席者には次を提出させると、アプリ単体で最低限の学習を確認できます。

- 指定lessonの完了記録
- 練習問題2問のコード
- 変更前後の出力
- 事後学習の説明1問
- Exit Ticket

## 14. AI利用時の評価

AI使用の有無だけで加点・減点しません。次を評価します。

- 問いと期待結果が明確
- 主要変数を説明できる
- 小さい入力で検証した
- エラーを読んで修正した
- 値または規則を自分で変更した
- 結果を過剰解釈しない
- 使用したプロンプトと採否を記録した

## 15. ネットワーク障害時

- 本文、問題、解答例はService Worker cacheがあれば閲覧可能
- 新しい端末でPyodideを未取得の場合、Python実行はできない
- 教員PCの実行結果を投影し、学生は予想とコード追跡を行う代替案を用意
- 学内ネットワークでCDNが制限される場合は、授業前に許可申請またはPyodideのself-hostを検討
